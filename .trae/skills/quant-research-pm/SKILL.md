# 量化研究项目管理

用于 EQ-MR-01（A 股短期反转）及同类量化研究项目。目标是让项目状态、决策、偏差和下一步始终可追溯，而不是写一份好看的汇报。

## 开始前先读

按顺序读取，不要凭记忆回答：

1. `docs/PROJECT_MEMORY.md`：目标、约束、决策链、研究设计、当前状态、技术债、红线。
2. `docs/PROJECT_PLAN.md`：范围、WBS、里程碑、风险登记、验收标准。
3. `docs/reports/` 下最近一份周报。
4. `configs/baseline.yaml` 与 `git log --oneline -10`：确认参数与实际进度。

如果文档与代码冲突，以代码和可复现结果为准，并在本次更新中修正文档。

## 每周流程

1. **收集事实**：查看本周 commit、结果表、日志；记录数据量、实验组合数、耗时。
2. **对比计划**：逐项标注完成/延期/取消，写清原因与影响，不写“进展顺利”。
3. **更新记忆**：只改 `PROJECT_MEMORY.md` 的第 3、7、8、9 节（决策、状态、技术债、下一步）。
4. **写周报**：新建 `docs/reports/YYYY-MM-DD-weekN.md`，按下方模板。
5. **过门禁**：逐项检查质量门禁；未通过项写入下周 P0。
6. **提交**：文档与代码分开提交，使用 Conventional Commits。

## 周报模板

```markdown
# 第 N 周周报（YYYY-MM-DD 至 YYYY-MM-DD）

## 一、本周结论（一句话）
## 二、完成事项（表格：日期 / 事项 / 产出 / 验收）
## 三、关键数字（数据量、实验数、耗时）
## 四、结果摘要（表格 + 必须列出的限制）
## 五、偏差分析（计划 / 实际 / 原因 / 影响 / 纠偏）
## 六、风险与阻塞（需要决策的事项）
## 七、下周计划（P0 / P1 / P2，每项带验收标准）
## 八、经验教训
```

## 质量门禁

每个里程碑结束必须逐项确认：

- [ ] 代码可运行，新增逻辑有中文注释
- [ ] 变量名为英文，表头/输出/文档为中文
- [ ] 表格列宽、对齐、小数位、百分比格式统一
- [ ] 结果可追溯到代码版本、参数与数据版本
- [ ] 无未来函数、无跨日混池、复权口径统一
- [ ] 毛收益与净收益、成本情景同时报告
- [ ] 更新了 `PROJECT_MEMORY.md` 当前状态
- [ ] 提交信息符合 `feat/fix/docs/chore/test`

## 研究红线

出现以下情况，停止执行并先问用户：

- 想改变研究问题、市场范围、样本区间或统计口径
- 想引用只有 5 只股票的结果作为市场结论
- 想用未复权价格做正式收益
- 想把 `reveral_summary.csv`（混池口径）写进报告
- 想把“t 值显著”直接写成“策略有效”
- 时间预算可能超过 8 周

## 表达规范

- 结论必须带证据与限制，格式：`结论 + 数字 + 样本 + 不能说明什么`。
- 不写“显著提升”“效果很好”这类无口径形容词。
- 简历素材只写有代码和结果支撑的内容；没有组合回测就不写收益率、夏普、回撤。
- 周报中的“完成”必须有文件、表格或 commit 作为证据。

## 重新基线

当实际进度落后超过一周：

1. 保留原里程碑，标注延期原因。
2. 按剩余时间重排 M1–M5，不压缩数据质量与统计检验。
3. 明确砍掉哪些 P2，保哪些 P0。
4. 在 `PROJECT_PLAN.md` 的变更记录中追加一行，并说明是否仍在 8 周上限内。

## 交付检查

报告定稿前，确认六项交付物齐全：研究报告、可复现代码、数据质量报告、实验结果表、风险分析、项目演示。缺一项就不算完成。
