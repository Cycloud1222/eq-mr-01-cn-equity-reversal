# T3.1：历史指数成分快照采集与幸存者偏差审计

## 研究动机

项目已有的 `src/download_data.py --source index800` 调用 `bs.query_hs300_stocks()` 和
`bs.query_zz500_stocks()` 时**未传日期**，得到的是查询时点的成分快照。
把此名单直接用于 2020—2025 年的历史横截面排序，可能遗漏当时在指数内、后来被调出的股票。

历史指数成分是独立于历史上市资格的一种条件：

- **历史上市资格**：上市日不晚于研究日，且研究日前尚未退市；
- **历史指数成员资格**：研究日指数确实包含该股票，且成员变更生效日未晚于研究日；
- **当日可交易性**：是否停牌、是否涨跌停、是否有可用成交价等。

三者不能互相代替。只检查 IPO 和退市日期，不会自动恢复以前被调出指数的股票。

## 本阶段范围：数据采集，不直接重跑策略

新脚本：`src/collect_historical_index.py`

接口：

- `bs.query_trade_dates(start_date, end_date)`：决定每月、每周或每天实际的交易日。
- `bs.query_hs300_stocks(date=query_date)`：按指定日期查询沪深 300 成分。
- `bs.query_zz500_stocks(date=query_date)`：按指定日期查询中证 500 成分。

严格分别存储「查询日期」和接口返回的「数据更新日期（updateDate）」，并校验后者不得晚于查询日期。默认严格模式下，超过 35 个自然日的旧快照报错；在显式 `--audit-only` 模式下，允许保存这些快照，但将其标记为「需复核」，不得直接用于正式回测。指数成分数量不符（如中证500返回499只）也会在审计表里标记。

**这个检查只是必要条件，不是历史成员资格绝对准确的证明。** 还须通过不同日期的实际成分差异、样本数量和指数公司正式公告交叉核对。

`data/raw/historical_index/`，重复运行会优先复用缓存。遇到更新日期晚于查询日、
数据太旧、重复股票、返回空值或非沪深 A 股代码时，不会假装采集成功。

**注意：** 成分数量应与指数名称相符，但不要直接认为任何不满 300/500 的结果都必然错误；
应先调查停牌、历史口径和接口范围，尤其在旧指数数据覆盖不完整时。

## 扩大日期后的口径区别

- `--frequency monthly --limit 0`：所有交易月末；可先观察 2020—2025 不同时点的成员变化。
- `--frequency weekly --limit 0`：每个交易周末；改善时间分辨率，但仍不代表周内每日生效成分。
- `--frequency daily --limit 0`：所有交易日；最适合为日频策略构建每日资格，不过请求数大，必须先验证数据源覆盖、速率与缓存。

月度和周度快照的中间日期**不能自动用月末、周末向前填充**：这可能在成员正式生效前引入未来信息。
即使对过去最近一次快照做向后沿用，也可能漏掉快照之间的成分调整。正式回测需以交易日生效时点的数据为准。

## 后续两道工程关口

### A. 下载覆盖

目前原始日线只覆盖约 799 只「当前成分」股票，历史指数成分中会有不少**不在**原有行情面板的证券。
在完成每日成分历史审计后，应生成历史成员代码并集，与 `data/raw/baostock/` 内现有数据做缺口比较，再下载缺失历史行情。

不能只把旧 799 只股票的行情与新历史成分表 `inner merge`，然后宣称消除了幸存者偏差；
这样会继续遗漏历史调出和退市的证券。

### B. 历史上市与退市核验

可用 `query_stock_basic()` 获取 IPO、退市日期、类型与当前上市状态，但需要检查数据源是否覆盖所有历史退市股票；
只用当前上市股票基础信息，同样无法修正幸存者偏差。

## 通过标准

- 试运行的三个查询日均为真实交易日。
- 两个指数的查询都返回非空、唯一、可解析的证券代码与更新日期。
- 更新日期不得在查询日之后，超龄快照不得静默混入。
- 报告各查询日期指数成分数量、最早更新日期与滞后天数。
- 不改变之前的 `cross_section_summary.csv` 和 `hac_robustness_summary.csv`；
  只有完整历史成分、行情覆盖与可交易性规则建立之后，才开展修正后的横截面研究。

## 采集阶段错误处理（2026-11-05 更新）

2021 年历史快照真实运行中出现两个需要研究者核查的现象：

- `2021-09-30` 查询中，中证500仅返回 **499只**，预期通常为500只。
- `2021-12-31` 查询中，沪深300数据更新日为 `2021-11-15`，相距 **46个自然日**，超过原有35天阈值。

这两项都**不能直接断言数据无效**，也不能被默默当作可信数据用于回测。更新日期未必是成员生效日期；超时阈值是研究项目自设警戒线。

为便于完成整个历史范围的**数据源审计**，新增可显式开启的审计采集模式：

```powershell
python src/collect_historical_index.py --frequency monthly --limit 0 --audit-only
```

此模式保留原始查询结果，并在标准化数据及审计摘要中增加 **审核状态**、**需复核原因** 两列。任何快照更新日晚于查询日期、代码重复、空表或不合法证券代码等明确结构错误仍会报错。默认不使用 `--audit-only` 时，超过阈值依然会停止，以防未经确认的超龄快照被当作已验证数据。

**“通过基础检查（待生效日核验）”也不代表已具有可用于正式历史回测的可靠资格。** 如需正式日频研究，应结合公告核对成分调整生效时点与 499 只异常来源。

此阶段输出仍放在忽略的 `data/processed` 中，并非最终已经验证的历史指数成分。完整范围采集后先筛选 `审核状态 == '需复核'` 的记录调查，再考虑行情补采与策略回测。
